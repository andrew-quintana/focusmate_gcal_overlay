# PRD 001 — Focusmate Calendar Overlay Chrome Extension (Initial Implementation)

## Problem & Goals

### Problem Statement
Users of Focusmate struggle to see time conflicts between their Google Calendar events and scheduled Focusmate sessions. Currently, users must manually check their calendar separately, leading to:
- Missed scheduling conflicts
- Double-booking of time slots
- Inefficient session planning
- Context switching between Focusmate and Google Calendar

This creates friction in the user's workflow and reduces the effectiveness of their time management.

### Goals
1. **Visual Conflict Detection**
   - Automatically detect and highlight Focusmate sessions that overlap with Google Calendar events
   - Provide immediate visual feedback without requiring manual calendar checks
   - Measured by: User reports of reduced scheduling conflicts

2. **Seamless Calendar Integration**
   - Display Google Calendar events directly within the Focusmate interface
   - Support read-only calendar access via OAuth
   - Measured by: Successful OAuth authentication rate > 95%

3. **User Configuration**
   - Allow users to configure which calendars to include
   - Enable customization of conflict highlight colors
   - Provide toggle for overlay visibility
   - Measured by: Options page usage and configuration persistence

4. **TypeScript Implementation**
   - Build entire extension using TypeScript for type safety and maintainability
   - Ensure all components (background, content, options, popup) are TypeScript-based
   - Measured by: 100% TypeScript codebase with no JavaScript files (except compiled output)

## Functional Requirements

### FR1: Extension Architecture (TypeScript)
1. **TypeScript Codebase**
   - All source code written in TypeScript (.ts files)
   - Type definitions for all data structures and API responses
   - Strict type checking enabled in tsconfig.json
   - Build process compiles TypeScript to JavaScript for Chrome extension

2. **Component Structure**
   - `background.ts` - Service worker with Google Calendar API integration
   - `content.ts` - Content script for DOM manipulation and overlay rendering
   - `options.ts` - Options page logic with settings management
   - `popup.ts` - Popup interface (if needed)
   - Shared type definitions in `types/` directory

### FR2: Google Calendar Integration
1. **Authentication**
   - Use `chrome.identity.getAuthToken()` for OAuth flow
   - Request `https://www.googleapis.com/auth/calendar.readonly` scope
   - Handle token expiration and refresh automatically
   - Support multiple calendar selection

2. **Event Fetching**
   - Fetch events for specified date range using Google Calendar API v3
   - Support `timeMin` and `timeMax` query parameters
   - Expand recurring events with `singleEvents=true`
   - Normalize events to internal format with timezone handling
   - Cache results for 60 seconds to reduce API calls

3. **Event Data Structure**
   - Store events with: id, calendarId, summary, startMs, endMs, allDay flag, htmlLink
   - Handle all-day events (date vs dateTime)
   - Exclude cancelled events
   - Support timezone conversion

### FR3: Focusmate Session Detection
1. **Session Source (Preferred: API)**
   - Fetch Focusmate sessions via public API if available
   - Use API key stored in extension options
   - Normalize to: id, startMs, endMs, title

2. **Session Source (Fallback: DOM Scraping)**
   - Detect session blocks in Focusmate DOM
   - Extract session identifiers and time ranges
   - Send parsed sessions to background script
   - Use multiple selector strategies for robustness

3. **Session Data Structure**
   - Consistent session key generation (prefer stable ID, fallback to time-based)
   - Support for session metadata (title, description if available)

### FR4: Conflict Detection
1. **Overlap Algorithm**
   - Implement interval overlap logic: `aStart < bEnd && aEnd > bStart`
   - Handle all-day events as full-day coverage
   - Support partial overlaps (any time intersection)
   - Generate conflict map: `Record<string, string[]>` (sessionKey -> eventIds[])

2. **Conflict Computation**
   - Compute conflicts in background service worker
   - Return conflict map with events and sessions
   - Support timezone normalization for accurate comparisons

### FR5: Overlay UI
1. **Overlay Rendering**
   - Create Shadow DOM container for style isolation
   - Position overlay on right side or bottom of Focusmate page
   - Display events in agenda or mini-timeline format
   - Show event time range, title, and calendar indicator

2. **Overlay Features**
   - Collapse/expand toggle button
   - Date range indicator (Today / This Week)
   - Filter toggle for all-day events
   - Clickable links to open events in Google Calendar
   - Responsive to Focusmate view changes

3. **Persistence**
   - Overlay persists across SPA route changes
   - Recreate overlay if DOM is removed
   - Use MutationObserver to detect page changes

### FR6: Conflict Highlighting
1. **Visual Styling**
   - Apply CSS class (e.g., `.fmcal-conflict`) to conflicting session elements
   - Inject styles via Shadow DOM or document head
   - Use configurable highlight color from settings
   - Add border, background color, or outline

2. **Reapplication**
   - Use MutationObserver on calendar grid container
   - Debounce updates (200ms) to avoid thrashing
   - Reapply styles when Focusmate UI re-renders
   - Support multiple selector strategies for DOM changes

### FR7: Options Page
1. **Settings Management**
   - Store settings in `chrome.storage.local`
   - Settings: overlayEnabled, conflictColor, calendarIds, focusmateApiKey, debugLogging
   - Provide UI for all configurable options
   - Validate user input (color format, API key format)

2. **Calendar Selection**
   - List available calendars from all Google accounts (support multiple accounts)
   - Support calendar groups in addition to individual calendars
   - Allow multi-select for calendar inclusion across accounts and groups
   - Default to primary calendar of the main account
   - Organize calendar list by account and group for clarity
   - Save selection to storage

## Risks / Open Questions

### Technical Risks

1. **Focusmate DOM Changes**
   - **Risk**: Focusmate UI updates could break session detection selectors. No stable DOM identifiers exist; React-based SPA with hashed class names.
   - **Mitigation**: Implement multiple selector strategies (accessibility labels, time text parsing, derived keys from time ranges). Use MutationObserver for re-renders. Treat DOM scraping as fallback; prefer Google Calendar as source of truth when sync is enabled.

2. **Google Calendar API Rate Limiting**
   - **Risk**: Excessive API calls could hit rate limits
   - **Mitigation**: Implement 60-second caching, batch requests, respect API quotas

3. **TypeScript Build Complexity**
   - **Risk**: Build configuration for Chrome extension may be complex
   - **Mitigation**: Use established tools (webpack/rollup), document build process clearly

4. **Timezone Handling**
   - **Risk**: Incorrect timezone conversion could cause false conflicts or missed conflicts
   - **Mitigation**: Use epoch milliseconds for all comparisons, normalize all times to UTC

### Resolved Questions

1. **Focusmate API Availability** ✅ **RESOLVED**
   - **Answer**: Focusmate provides a public, user-scoped API for integrations, but it is **not a fully productized or strongly versioned developer platform**. Stability guarantees are limited.
   - **Endpoints**: There is an endpoint to fetch sessions (historical and upcoming), but explicit, well-documented arbitrary date-range querying is not guaranteed. Date filtering may be coarse or implicit.
   - **Authentication**: Focusmate API key generated in user's account settings (no OAuth, no refresh tokens).
   - **Critical Insight**: If the user has **Focusmate → Google Calendar sync enabled**, Focusmate sessions already appear as Google Calendar events. In this case, **date ranges can be derived directly from Google Calendar**, avoiding reliance on Focusmate's session-range API semantics entirely. This is the most reliable path for time-window alignment.
   - **Design Implication**: Treat Focusmate API as **optional**, not foundational. Prefer **Google Calendar as the source of truth for time ranges**, especially when Focusmate sync is enabled.

2. **Focusmate Session DOM Structure** ✅ **RESOLVED**
   - **Stable Identifiers**: There are **no guaranteed stable DOM identifiers**. Focusmate is a React-based SPA; class names may be hashed or change across releases.
   - **Data Attributes**: Sometimes present, but **not reliably** and not documented. Session IDs may not be present in the DOM.
   - **Rendering**: Focusmate renders sessions differently depending on context (upcoming view, calendar/day view, week view, post-session views). Each view may use different React components and produce different DOM trees.
   - **Design Implication**: Use **derived keys** (e.g., start time + end time, optionally with label hash) rather than assuming an ID attribute. Implement multiple selector strategies (accessibility labels → time text parsing). Use MutationObserver to detect re-renders. Design for selector fragility and re-rendering as a first-class constraint.

3. **Calendar Selection UI** ✅ **RESOLVED**
   - **Number of Calendars**: Unlimited, but default to the main calendar.
   - **Calendar Groups**: Support multiple accounts and calendar groups, not just individual calendar selection.
   - **Design Implication**: Options page must support multi-select for calendars across multiple accounts and calendar groups, with primary calendar as default.

## Assumptions & Dependencies

### Assumptions
1. Focusmate is a SPA that updates dynamically; DOM may change on route changes
2. Google Calendar API v3 will remain available and stable
3. Chrome Identity API will continue to support OAuth flows
4. Users have a Google account with at least one calendar
5. Focusmate sessions may be available via API (optional) or DOM scraping (fallback); **Google Calendar is preferred as source of truth** especially when Focusmate→Google Calendar sync is enabled
6. TypeScript compilation to JavaScript is acceptable for Chrome extension runtime
7. Focusmate DOM has no stable identifiers; session keys must be derived from time ranges and other observable attributes
8. Users may have multiple Google accounts with multiple calendars and calendar groups

### Dependencies
1. **Chrome Extension APIs**: Manifest V3, chrome.identity, chrome.storage, chrome.runtime
2. **Google Calendar API**: v3 REST API with OAuth 2.0
3. **TypeScript**: Version 5.x or later
4. **Build Tool**: webpack, rollup, or similar for TypeScript compilation
5. **Focusmate Web App**: https://app.focusmate.com/* (target domain)
